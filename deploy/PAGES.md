# Квизориум без сервера: GitHub Pages

Версия из ветки `p2p-pages` работает без игрового сервера. GitHub Pages отдаёт только страницу и встроенные паки, а комнаты живут в браузерах игроков.

## Как это устроено

- **Поиск друг друга.** Браузеры находят друг друга через публичные Nostr-реле (библиотека [Trystero](https://github.com/dmotz/trystero)) и дальше общаются напрямую по WebRTC.
- **Список комнат** идёт прямо через Nostr-реле, без соединения между браузерами. Каждая комната объявляет себя раз в 10 секунд, а новичок при входе просит всех объявиться сразу. Поэтому комнаты видит даже тот, у кого прямые соединения не проходят.
- **Реле заданы явно.** Для соединений используются несколько небольших реле из списка Trystero, которые проверены и пропускают нужные сообщения. Крупные реле вроде damus режут поток сообщений при установке соединения и банят за это. Для списка комнат, где сообщений мало, добавлены и крупные.
- **WMV, AVI, WMA и другие форматы, которые браузеры не играют,** браузер ведущего перекодирует в MP4 при загрузке пака (ffmpeg.wasm, около 32 МБ, скачивается только для таких паков). Это примерно 3 секунды на ролик. Если файл перекодировать не удалось, игроки видят на его месте надпись.
- **Аватары** передаются один раз на человека, уменьшенными до 128 px: в обновлениях комнаты едет только короткая метка.
- **Хранитель комнаты.** Комнату ведёт браузер одного из участников. Он считает игру той же логикой, что и сервер, и раз в секунду рассылает копию состояния и пака всем участникам.
- **Хранитель пропал.** Его место по одному и тому же правилу у всех занимает следующий: сначала ведущий, иначе участник с наименьшим номером. Игра продолжается с того же места, к таймеру добавляется 5 секунд.
- **Нет прямой связи — через другого.** Если два браузера не соединяются напрямую, сообщения идут через участника, связанного с обоими.
- **Совсем нет прямой связи — через реле.** Участник, который ни с кем не соединился, через 5 секунд начинает раз в 3 секунды здороваться с хранителем прямо через Nostr-реле, и хранитель отвечает тем же путём. Сообщения идут пачками, сжатыми gzip; из обновлений комнаты отправляется только последнее. Так можно играть: выбирать, жать «Ответить», писать ответ, кликать по картинке. Но картинки, звук и видео этим путём не идут, поэтому вопросы с медиа такой игрок видит без них, и его не ждут при загрузке медиа.
- **Значки связи.** У каждого человека в комнате точка: зелёная — хранитель связан с ним напрямую, жёлтая — через другого участника, оранжевая — через реле. У того, кто пропал, вместо точки надпись «Не в сети» и отсчёт до того, как комната его отпустит. Сам игрок на запасном канале видит об этом полосу под верхней панелью, а потерявший связь — «переподключаемся…».
- **Вышел и вернулся.** Ведущий или игрок, который закрыл вкладку, после возврата на сайт сам попадает обратно в комнату на своё место.
- **Все ушли.** Последнюю копию комнаты каждый участник хранит у себя сутки. Кто первым вернётся по коду комнаты, тот её и поднимет.

## Публикация

1. Создайте на GitHub **публичный** репозиторий. Бесплатный Pages работает только с публичными.
2. Отправьте туда ветку:
   ```bash
   git remote add origin https://github.com/ВАШ_НИК/kvizorium.git
   git push -u origin p2p-pages
   ```
3. В репозитории: **Settings → Pages → Source: GitHub Actions**.
4. Во вкладке **Actions** дождитесь зелёной галочки у «Pages». Сборку можно запустить и вручную: Run workflow.
5. Игра будет по адресу `https://ВАШ_НИК.github.io/kvizorium/`.

## Локально

```bash
npm run dev:p2p
```

Откройте `http://localhost:5174`. Вторым игроком удобно заходить с другого адреса, например `http://peer.localhost:5174`: так у вкладки будет свой профиль.

## Ограничения

- **Ответы видны всем, кто полезет в инструменты разработчика.** Копия комнаты и пака есть у каждого участника, потому что иначе нельзя пересадить хранителя. Для игр с друзьями это нормально.
- **Вход в комнату ждёт до 35 секунд**, если комната есть в списке: первое соединение через интернет бывает небыстрым. Если за это время не удалось связаться ни с кем из её участников, игрок видит, что дело в сети (VPN, строгий NAT), а не в том, что комнаты нет.
- **Нет TURN-сервера, но есть пересылка.** Если два браузера не могут соединиться напрямую (строгий NAT у обоих), сообщения идут через третьего участника, связанного с обоими. Каждый участник раз в 3 секунды сообщает, с кем он связан, и по этим данным строится маршрут. Если игрок за 15 секунд не может достучаться до хранителя, он переподключается сам. Кто не соединился вообще ни с кем, играет через реле (см. выше), но без медиа.
- **Подменить себя за другого технически можно.** Номер игрока хранится в браузере и ничем не подписан.
- **Все на сайте в одной общей сети.** Это хорошо работает для десятков человек онлайн одновременно, но не для тысяч.
- **Нет топа паков и истории игр:** их негде хранить.
